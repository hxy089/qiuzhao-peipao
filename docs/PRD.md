## 1. 背景与问题

PM 求职者在秋招投递中面临三个具体问题（待问卷验证，目标 30 份）：

1. **重复劳动**：每投递一个岗位，需手动改写简历 20-30 分钟，秋招投递 30+ 家即产生大量重复工作
2. **取舍无方法**：求职者普遍有多段实习、项目、校园经历，针对某个 JD「选哪几段、怎么改写」依赖感觉，无方法沉淀
3. **通用工具不解决真问题**：现有 AI 简历工具（含通用大模型对话）本质是「文本改写器」——逐句润色，不理解简历的本质是**经历与岗位的匹配决策**，也不懂 PM 求职语境（什么经历该突出、量化怎么写、大厂与创业公司侧重差异）

## 2. 产品定位

**一句话**：上传历史简历构建结构化经历库，针对每个 JD 完成经历取舍与定制改写的秋招投递工作台。

**差异化**（vs 市面 AI 简历工具 / 裸 GPT）：
- **改写器 → 组装器**：简历不是被「改」出来的，是从结构化经历库按 JD「组装」出来的
- **通用模型 → 垂直知识**：内置由真实 PM JD 与求职经验帖提炼的知识库，注入每次分析
- **一次性输出 → 版本管理**：按公司-岗位保存多个版本，持续对话迭代，简历只存用户本地（隐私卖点）

**愿景与分期**（北极星愿景为「秋招陪跑」，v0 只做投递前的简历定制环节）：
- v0（本 PRD）：经历库 + JD 分析 + 组装改写 + 对话迭代 + 版本管理
- 二期：面试准备模式（基于过筛版本生成预测问题与模拟追问）、投递结果追踪（先做手动标记）
- 三期：AI 自动抓取求职信息源、数据看板、账号体系、知识库 RAG 化

## 3. 目标与非目标

**v0 目标**
- 用户可在 5 分钟内完成「上传简历 → 输入 JD → 获得定制简历」全流程
- 改写内容 100% 可溯源（每处改动标注原因，禁止编造事实）
- 全程数据仅存用户浏览器本地，无后端

**v0 非目标（明确不做）**
- 面试准备、投递结果追踪、简历评分、ATS 模拟
- 账号体系、云端同步
- 自动抓取外部信息源
- 简历模板美化/排版设计（输出统一 markdown 结构 + 浏览器打印样式）

## 4. 目标用户与核心场景

**目标用户**：产品经理求职者（应届生/实习生为主），有一定线上社群触达（牛客、小红书、求职群）

**核心场景 1（首次使用）**：小红书看到产品 → 上传 1-3 份不同时期的历史简历 → 系统合并去重生成经历时间线 → 快速浏览确认
**核心场景 2（日常投递）**：复制目标岗位 JD → 粘贴 → 查看经历取舍建议与缺口分析 → 生成定制简历 → 对话微调 → 保存版本 → 打印导出 → 投递

## 5. 核心用户流程

### 5.1 首次使用（构建经历库）
```
进入产品 → 空态引导 → 上传 1~3 份 PDF（或粘贴文本）
→ PDF 解析为纯文本 → LLM 提取+合并+按时间排序 → 结构化经历库
→ 用户在经历库页逐条查看/编辑 → 确认（存 localStorage）
```

### 5.2 日常投递（定制简历）
```
新建投递（填公司名/岗位名 + 粘贴 JD 全文）
→ AI 分析 JD（要求拆解 + 关键词）
→ AI 经历级匹配（每段经历：选中/舍弃 + 理由）+ 缺口分析
→ 组装生成定制简历（markdown，改动点高亮可切换查看）
→ 对话式修改（可多轮）
→ 保存版本（关联公司-岗位）→ 复制 / 打印导出
```

## 6. 功能需求

### F1 简历上传与解析（P0）
- 支持 PDF 上传，单次最多 3 份；同时提供「粘贴文本」入口
- 使用 pdf.js 提取纯文本
- **边界**：图片型/扫描件 PDF 提取结果为空或乱码 → 提示「解析失败，请粘贴文本」并高亮粘贴入口

### F2 经历库构建（P0）
- LLM 从 1-3 份简历文本中提取全部经历（实习/项目/校园/竞赛/开源）
- **合并规则**：同一经历（同公司+同岗位+时间段重叠）合并为一条；bullets 取并集去重，保留最完整表述；记录来源文件
- 按 start 时间倒序排列，展示为「经历时间线」
- 用户可对每条经历进行编辑、删除（v0 不做手动新增与拖拽排序）
- **边界**：某份简历解析质量差 → 允许删除该来源并重试；经历条目允许直接改文本

### F3 JD 分析（P0）
- 输入：岗位名（可选）、公司名（可选）、JD 全文（必填）
- LLM 输出结构化结果：硬性要求 / 软性要求 / 关键词（中英文）/ 隐含能力项，并对推断项标注置信度
- **约束**：JD 未提及的内容不臆测为要求

### F4 经历选择与简历组装（P0，核心功能）
- 基于 JD 分析结果 + 经历库，AI 输出：
  1. **选择**：每段经历标记「强相关/相关/舍弃」+ 一句话理由
  2. **改写**：选中经历的 bullets 重写——对齐 JD 关键词、突出量化结果、调整 bullet 顺序
  3. **缺口**：JD 要求但经历库无法支撑的点，单独列出供参考（**不写入简历**）
  4. **成品**：定制简历 markdown（结构：基本信息 → 教育背景 → 实习经历 → 项目经历 → 技能）
  5. **改动清单**：每处改动的位置、改前/改后、原因
- **防幻觉硬约束（写入 prompt）**：所有事实与数字必须来自原经历库；只允许重组、措辞优化、顺序调整与相关经历突出；禁止编造数据、经历、时间

### F5 对话式迭代（P0）
- 在生成的简历基础上多轮对话修改（上下文含当前简历全文 + JD 分析摘要 + 经历库）
- 每轮返回更新后全文 + 增量改动清单
- 支持指令示例：「突出数据分析能力」「删掉这段」「更精炼」「把 XX 经历放前面」

### F6 版本管理（P0）
- 每次投递创建一个「投递卡」（公司名-岗位名-JD-创建时间）
- 保存后生成版本（含简历全文 + 改动历史），按投递卡归档
- 版本列表支持查看、继续编辑（继续对话）；v0 不做版本 diff 对比视图
- 数据全部存 localStorage（见 §8）

### F7 数据埋点（P1）
- 本地计数：打开次数、JD 分析次数、版本生成数、导出数、活跃日期
- 设置页展示统计，并附「欢迎把截图发给我」的自愿反馈引导（v0 无后端，数据回收靠自愿）

## 9. AI 方案

### 9.1 调用链（4 个 Prompt）
| # | Prompt | 输入 | 输出 |
|---|---|---|---|
| P1 | 经历库提取与合并 | 1-3 份简历纯文本 | 经历库 JSON（§8 结构），合并去重、时间倒序；不翻译不改写不补充 |
| P2 | JD 分析 | JD 全文 + 知识库注入 | 要求拆解 JSON，推断项标置信度 |
| P3 | 经历匹配 + 组装 | 经历库 JSON + P2 结果 | 选择理由 + 改写简历 markdown + 改动清单 + 缺口 |
| P4 | 对话迭代 | 当前全文 + 上下文 + 用户指令 | 更新全文 + 增量改动清单 |

- P3/P4 共用同一套防幻觉约束（见 F4）
- P1 输出 JSON 需做解析容错（JSON repair + 校验字段完整性，失败自动重试 1 次）
- 所有调用展示加载态；单次生成目标 < 30s

### 9.2 知识库注入
- `knowledge/pm-resume-checklist.md`（PM 简历写法：量化、STAR、AI 经历写法、大厂 vs 创业侧重）
- `knowledge/pm-jd-patterns.md`（30+ 真实 PM JD 提炼的高频要求，按频次排序）
- 两文件合计控制 2-3k token，**全量注入 P2/P3/P4 的 system prompt**；v0 不做 RAG
- 注入时读取文件内标注的 kbVersion，写入 settings 便于追溯

### 9.3 模型接入
- 用户自带 API Key（BYOK），支持 OpenAI 兼容接口（可配 base URL）；Key 存 localStorage 不出浏览器
- 演示模式不调用任何 API

## 10. 非功能需求

- **隐私**：零后端，全部数据存用户浏览器；首访弹一次性说明
- **成本**：静态站，GitHub Pages 免费部署；用户自担 LLM 调用成本
- **兼容**：Chrome/Edge 最新版优先
- **导出**：复制到剪贴板 + window.print()（A4 打印样式，隐藏界面元素）导出 PDF

## 12. 异常与兜底

| 场景 | 处理 |
|---|---|
| PDF 为图片型/解析为空 | 引导粘贴文本 |
| LLM 返回 JSON 不合法 | repair + 重试 1 次，仍失败提示重试 |
| JD 粘贴不完整/过短（<50 字） | 提示补充岗位信息 |
| 经历库为空时进工作台 | 引导先去经历库页 |
| localStorage 满 | 提示导出备份并清理旧版本 |
| API 调用报错（余额/网络） | 明确错误文案，不吞异常 |
