# PM 简历写法 Checklist

> 知识库版本：v0.1（手写首版基线）。待收集 30+ 篇 PM 求职经验帖后升级为提炼版。
> 用途：注入 AI 分析 prompt，约束简历改写时的写法与判断标准。

## 1. 结构规范

- 标准顺序：基本信息 → 求职意向（可选）→ 教育背景 → 实习经历 → 项目/校园经历 → 技能
- 应届生/实习生简历一页为佳，最多两页；每段经历 2-4 条 bullet
- 经历按时间倒序；与目标岗位相关的经历往前放、写多条，无关经历压缩为一条或舍弃
- 教育背景：学校 + 学历 + 专业 + 起止时间即可；GPA/排名高才写

## 2. Bullet 写法

- 动词开头：负责/主导/搭建/推动/沉淀/输出/独立完成，避免「参与」「帮忙」等弱动词
- 一条 bullet 只讲一个点：动作 + 方法/场景 + 量化结果
- 长度 ≤ 2 行；超过就拆条
- STAR 压缩为「结果 + 关键动作」，不写背景铺垫
- 量化维度清单：规模（用户数/数据量/时长）、增长（提升 x%）、效率（人力节省/时长缩短）、覆盖（城市/业务线/人数）、收入与成本
- 没有精确数字时用量级：10+、50+、800+ 条、3w+ 条，但不得编造

## 3. AI/大模型经历怎么写（2026 秋招重点考察）

- 写清三要素：业务场景 + AI 方法（Prompt/RAG/评测/Agent/意图识别等）+ 效果指标
- 评测与标注经历要写出方法论：维度设计、数据规模、SOP 沉淀——面试官考察的是「懂不懂 AI 的不确定性管理」
- 工具能力写进技能区：Claude Code、Dify、Coze、Prompt 工程等；有个人项目必须写，附链接
- 避免堆砌模型名词；写「用什么能力解决了什么业务问题」

## 4. 大厂 vs 创业公司侧重差异

- 大厂：写清协作链路（协同多方角色）、流程规范（BRD/PRD、评审、上线、观测）、指标口径；体现「在复杂组织里推动事情」
- 创业公司/新业务：强调从 0 到 1、独立负责、快速迭代与结果
- 同一段经历投不同公司时，侧重点应调整——这正是按 JD 定制简历的价值所在

## 5. 常见错误

- 流水账式罗列工作内容，无结果无量化
- 一份简历投所有岗位，与 JD 无关的经历占大量篇幅
- 夸大或编造数据（面试必被追问口径）
- 「参与」「协助」开头且无任何产出物
- 技能区罗列十几项但都写「了解」

## 6. 与 JD 对齐原则

- JD 高频关键词应在 bullet 中自然复现（不要机械堆砌，不改变事实）
- 经历取舍标准：与岗位核心要求强相关 > 弱相关 > 无关；强相关经历可展开 3-4 条，无关经历舍弃
- JD 要求但简历没有的，宁可留白（面试再解释），绝不编造
