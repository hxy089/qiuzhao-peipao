# PM 岗位 JD 高频要求模式

> 知识库版本：v0.1（手写首版基线，基于对 PM 招聘市场的通用认知）。
> **待办**：收集 30+ 份真实 PM JD 后，用 Claude Code 重新提炼本文件的频次排序与表述，升级为 v0.2。
> 用途：帮助 AI 在单份 JD 短/模糊时，推断要求的真实含义与权重；并作为缺口分析的基准。

## 1. 硬性要求（按常见频次排序，v0.1 为估计）

1. **需求分析与 PRD 撰写**——几乎 100% 出现；考察独立产出 PRD 的能力与规范意识
2. **数据分析能力**——约 80%；通常指 SQL 取数 + 指标定义 + 用数据验证决策；明确写 SQL/Python 的约一半
3. **跨团队协作与项目推进**——约 80%；考察推动研发/设计/运营落地的能力
4. **用户调研与竞品分析**——约 60%；问卷、访谈、NPS 分析、竞品拆解
5. **AI/大模型相关**——AI 产品岗约 100%，泛产品岗约 40%（2026 年趋势上升）；Prompt 工程、RAG、评测、Agent、意图识别等
6. **A/B 实验与增长**——策略/增长岗高频；实验设计、指标显著性、迭代闭环
7. **Axure/Figma 原型**——约 30%，多见于 C 端产品岗

## 2. 软性要求模式

- 沟通表达、Ownership、抗压（几乎必现，权重参考）
- 好奇心/学习能力：AI 岗位语境下常指「跟进模型能力边界变化」
- 业务理解：B 端岗强调理解业务流程与降本诉求，C 端强调用户视角

## 3. JD 黑话解读（AI 判断 JD 时使用）

| JD 表述 | 实际考察 |
|---|---|
| 「从 0 到 1」 | 无既有方案可参考，考察独立定义问题的能力；有 0-1 经历者优先级最高 |
| 「北极星指标」「数据驱动」 | 会看大盘指标、能拆解指标、用数据说话 |
| 「跨部门/多方协同」 | 无职权推动能力，大厂尤其看重 |
| 「有 AI 产品经验优先」 | 加分项而非门槛，可用评测/标注/Prompt 调优等实操经历满足 |
| 「熟悉大模型能力边界」 | 知道模型能做什么/不能做什么，设计过兜底与评测 |
| 「逻辑思维能力强」 | 面试用案例题考察，简历上体现为结构化的项目描述 |

## 4. 缺口分析基准

判断简历「缺什么」时，参照以下优先级（v0.1 基线）：
1. JD 硬性要求中简历完全无证据的 → 高优缺口
2. 目标岗位类型（AI/策略/C端/B端）的通用要求中无证据的 → 中优缺口
3. 仅 JD 一处提及且为「优先」字样的 → 低优，不出现在缺口建议中

缺口建议必须可行动（如「补充 SQL 取数经历」「面试中以 xx 经验迁移说明」），不接受「加强 xx 能力」这类空话。
